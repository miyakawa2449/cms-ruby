## 📋 Phase 6 の全体像

Phase 6 では、ポートフォリオCMSのセキュリティを強化します。既存の基本的なセキュリティ機能（Devise認証、Rack::Attack）を拡張し、より堅牢なセキュリティ体制を構築します。

---

## 🎯 Phase 6 の目的

### 1. セキュリティヘッダーの最適化

**現状**: CSP が開発環境のみ設定、HSTS が未設定

**目標**: すべての推奨セキュリティヘッダーを設定

- Content Security Policy (CSP)
- X-Frame-Options（クリックジャッキング対策）
- X-Content-Type-Options（MIME スニッフィング対策）
- Strict-Transport-Security (HSTS)（本番環境のみ）
- Referrer-Policy
- Permissions-Policy

### 2. 監視・ログ機能の強化

**現状**: セキュリティイベントのログが不十分

**目標**: すべてのセキュリティイベントをログに記録

- ログイン成功/失敗
- ログアウト
- アカウントロック/アンロック
- 管理画面への不正アクセス試行
- Rack::Attack によるブロック

### 3. セキュリティテストの充実

**現状**: セキュリティテストが不足

**目標**: 100件以上のセキュリティテスト作成

- セキュリティヘッダーのテスト
- 認証・認可のテスト
- レート制限のテスト
- 入力検証のテスト
- CSRF 対策のテスト
- セッション管理のテスト

### セキュリティレイヤー

1. **Rack Middleware レイヤー**
   - Rack::Attack: レート制限、ブロックリスト
   - SecureHeaders: セキュリティヘッダー
   - CSRF Token: CSRF 対策

2. **Application レイヤー**
   - Devise: 認証・認可
   - SecurityLogger: セキュリティイベントのログ記録
   - Input Validation: 入力検証・サニタイゼーション

3. **Database レイヤー**
   - パラメータ化クエリ: SQL インジェクション対策

## 🔄 処理フロー

### ログイン処理フロー

```
1. ユーザーがログインフォームを送信
   ↓
2. Rack::Attack がレート制限をチェック
   ├─ 制限超過 → 429 エラー + ログ記録
   └─ OK → 次へ
   ↓
3. Devise が認証処理
   ├─ 成功 → SecurityLogger.log_login_success
   └─ 失敗 → SecurityLogger.log_login_failure
   ↓
4. アカウントロック判定（5回失敗）
   ├─ ロック → SecurityLogger.log_account_locked
   └─ OK → 次へ
   ↓
5. セッション作成 + セキュリティヘッダー付与
   ↓
6. 管理画面へリダイレクト
```

### API リクエスト処理フロー

```
1. API リクエスト受信
   ↓
2. Rack::Attack がレート制限をチェック
   ├─ 認証済み → 300回/分
   └─ 未認証 → 60回/分
   ↓
3. 制限超過判定
   ├─ 超過 → 429 エラー + Retry-After ヘッダー
   └─ OK → 次へ
   ↓
4. コントローラー処理
   ↓
5. レスポンス返却 + セキュリティヘッダー
```
