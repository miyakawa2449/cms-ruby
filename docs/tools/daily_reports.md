# 日々の作業記録システム

## 📝 概要
このシステムは、日々の作業内容を自動的にGit情報と合わせて記録するためのツールです。プロジェクトの進捗管理と知識の蓄積を効率化します。

## 🛠 システム構成

### ファイル一覧
- `create_daily_report.sh` - 作業報告書生成スクリプト
- `.aliases` - 便利なエイリアスコマンド集
- `reports/` - 日付別作業報告書保存フォルダ
- `docs/tools/daily_reports.md` - この使用方法ドキュメント

## 🚀 使用方法

### 基本コマンド
```bash
# 基本的な作業報告書を作成
./create_daily_report.sh

# タイトル付きで報告書を作成
んbんbnんbんbん./create_daily_report.sh "API設計完成報告"
./create_daily_report.sh "Phase 2環境構築開始"
./create_daily_report.sh "バグ修正完了"
```

### エイリアス設定（推奨）
```bash
# エイリアス読み込み
source .aliases

# 短縮コマンドで報告書作成
report "データベース設計完了"
report "今日の作業完了"

# 今日の報告書一覧表示
today-reports

# 最新の報告書をVS Codeで開く
latest-report

# プロジェクト状況確認
project-status
```

### 専用エイリアス（作業タイプ別）
```bash
report-phase     # "Phase進捗報告"
report-feature   # "機能実装報告"  
report-bug       # "バグ修正報告"
report-design    # "設計変更報告"
```

## 💡 活用例

### 1. セッション終了時の記録
```bash
# 基本パターン
report "今日のセッション完了"

# 具体的なタイトル
report "Phase 1仕様策定完了報告"
report "データベース設計とAPI設計完成"
```

### 2. マイルストーン達成時
```bash
report-phase  # Phase進捗報告として記録
report "Phase 1完全完了 - Phase 2移行準備"
```

### 3. 重要な機能実装後
```bash
report-feature  # 機能実装報告として記録
report "ユーザー認証システム完成"
report "検索機能のパフォーマンス改善"
```

### 4. バグ修正・問題解決後
```bash
report-bug  # バグ修正報告として記録
report "レスポンシブデザインの表示問題修正"
```

### 5. 設計変更時
```bash
report-design  # 設計変更報告として記録
report "API エンドポイント構造見直し"
report "データベーススキーマ最適化"
```

## 🔄 推奨ワークフロー

### セッション開始時
```bash
# 1. プロジェクト状況確認
project-status

# 2. 昨日の報告書確認（あれば）
latest-report
```

### 作業中
```bash
# 重要な変更をこまめにコミット
git add .
git commit -m "機能実装完了"
```

### 区切りごと
```bash
# 作業記録作成
report "午前中の作業完了"
report "API実装完了"
```

### 一日終了時
```bash
# 今日の報告書確認
today-reports

# 最終報告書作成
report "本日の作業完了"
```

## 📊 レポート分析・活用

### 週次レビュー
```bash
# 今週の報告書を確認
ls reports/2025-11-2*/

# 各日の進捗確認
cat reports/2025-11-28/1st.md | grep "プロジェクト状況"
```

### 月次レビュー
- `reports/` フォルダで月間の作業履歴を確認
- 各報告書の「所感・学び」セクションで振り返り
- Git情報から作業ペースや変更頻度を分析

### プロジェクト進捗トラッキング
- 各報告書の「プロジェクト状況」で進捗推移を確認
- 「完了したタスク」でマイルストーン達成状況を把握
- 「課題・問題点」で継続的な改善ポイントを特定

## ⚡️ Tips・ベストプラクティス

### VS Code連携
- 報告書作成時に自動でVS Codeで開かれます
- Markdownプレビュー（`Cmd+Shift+V`）で見やすく確認
- 作業しながらリアルタイムで報告書を更新

### Git統合の活用
```bash
# コミットする前に報告書作成（推奨）
./create_daily_report.sh "機能実装完了"
# この時点で最新のGit情報が正確に記録される

git add .
git commit -m "機能実装とドキュメント更新"
```

### 継続のコツ
1. **小さな作業でも記録** - 習慣化が重要
2. **テンプレート活用** - 全項目を埋める必要はない
3. **重要な学びは必須** - 「所感・学び」セクションを重視
4. **定期的な振り返り** - 週次で `today-reports` を確認

### エラー対処
```bash
# スクリプトに実行権限がない場合
chmod +x create_daily_report.sh

# VS Codeが開かない場合
code --version  # VS Codeがインストールされているか確認

# 今日のフォルダが見つからない場合
mkdir -p reports/$(date +"%Y-%m-%d")
```
