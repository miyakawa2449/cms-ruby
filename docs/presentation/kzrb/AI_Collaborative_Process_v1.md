## 1. 目的と基本理念
本プロセスは、AI（Claude Code）を「単なるコード生成ツール」ではなく「開発パートナー」として位置づけ、**「開発スピードの最大化」**と**「コンテキスト（文脈）の資産化」**を同時に達成することを目的とする。

### 成功の方程式：人間3：AI7の黄金比
* **人間 (30%) - Core Value**:
    * **Vision**: 「なぜ作るか」「何を作るか」の構想
    * **Judgment**: Go/No-Goの判断、優先順位の決定
    * **Responsibility**: 最終的な品質責任、アーキテクチャ決定
* **AI (70%) - Labor**:
    * **Implementation**: ボイラープレート記述、単体テスト作成、単純なCRUD実装
    * **Research**: エラー調査、ライブラリ選定、ドキュメント要約
    * **Documentation**: 議事録作成、README更新、進捗レポート作成

## 3. 開発フェーズとアクション (Level 1-6)

### Phase 1: 立ち上げとプロトタイピング (Level 1-2)
**目標**: 圧倒的な速度で「動くもの」を作り、合意形成を行う。

1.  **Generate (Level 1)**:
    * 自然言語でUI/機能を指示。「ログイン画面を作成して」等。
    * **原則**: 細かいコード指示はしない。目的とイメージを伝える。
2.  **Fix by Visual (Level 2)**:
    * 修正指示は「スクリーンショット」で行う。
    * 具体的なCSSクラス名ではなく、「ここが重なっている」「もっと余白を」と指摘する。

### Phase 2: 実装とコンテキスト管理 (Level 3-4)
**目標**: 開発の継続性を担保し、AIの「健忘症」を防ぐ。

1.  **Session Start (Level 3)**:
    * 作業開始時は必ずコンテキスト復帰コマンドを実行する。
    * コマンド例: `session-start` (前回の文脈をロード)
    * `session-start`コマンドの内容はプロジェクト形式によるため、Claude Code と相談の上で、claudeコマンドを作成し、CLAUDE.mdに記述する
2.  **Progress Report (Level 4)**:
    * セッション終了時、必ず進捗を記録する。
    * コマンド例: `add-report`
    * **記録内容**: 変更ファイル数、追加行数、達成したタスク、次回の課題。
    * `add_report`コマンドの内容はプロジェクト形式によるため、Claude Code とフォーマット及び保存先を相談の上で、claudeコマンドを作成し、CLAUDE.mdに記述する

### Phase 3: 資産化とガバナンス (Level 5-6)
**目標**: プロジェクト固有の知識を蓄積し、品質を自動統制する。

1.  **Rule Definition (Level 5)**:
    * プロジェクトルートに `CLAUDE.md` を配置する。
    * コーディング規約、アーキテクチャ選定理由、NGパターンを記述。
    * AIに「迷ったら `CLAUDE.md` を読め」と徹底する。
2.  **Context Permanence (Level 6)**:
    * Claude.ai の `Projects` 機能に設計書・仕様書をアップロード。
    * 長期的な文脈（Why）をAIに保持させる。

## 4. 品質保証プロセス (Automated Governance)

### リファクタリング予約
* プロトタイプ期間中は「冗長さ」を許容する。
* ただし、**「3週間後のリファクタリング」**をタスクとして登録し、AIに実施させる。

### 自動チェック
`CLAUDE.md` に以下の基準を設け、AIに自己レビューさせる。
* 1メソッドは20行以内か？
* クラスの依存関係は適切か？
* 変数名は命名規則（`CLAUDE.md`記載）に従っているか？

## 5. ロール定義

| ロール | 担当者 | 役割 |
| :--- | :--- | :--- |
| **Architect / PM** | **人間** | フェーズ定義、設計整合性チェック、AIへの「待て」の指示 |
| **Lead Developer** | **AI** | 実装、テストコード作成、リファクタリング実行 |
| **QA Assistant** | **AI** | バグ要因の列挙、エッジケースの指摘 |

## 6. 免責と心構え
* **「コードを書く時間は終わった」**: 人間はアーキテクチャとコアロジックに熱中する。
* **「疑う勇気」**: AIの提案（知識）は常に人間の直感（嗅覚）でフィルタリングする。
