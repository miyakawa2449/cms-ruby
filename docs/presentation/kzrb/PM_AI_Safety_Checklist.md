# PM用：AI暴走防止チェックリスト

本チェックリストは、Claude Code を用いた開発において、AIの「暴走（勝手な実装、仕様の空中分解、コンテキスト喪失）」を防ぎ、人間が主導権を握り続けるための確認項目である。

---

## ✅ Phase 0: セッション開始前 (Context Loading)

- [ ] **「現在はどのフェーズか？」を言語化したか？**
    * 例：「今は設計フェーズ」「今はプロトタイプフェーズ」「今はリファクタリングフェーズ」
- [ ] **前回の `report` を確認したか？**
    * 前回どこで終わり、今日何をする予定だったかを把握しているか。
- [ ] **`session-start` コマンド（または同等の文脈復帰）を実行したか？**
    * AIは「初対面」の状態になっていないか確認する。
- [ ] **`CLAUDE.md` のルールに変更・追加はないか？**
    * 新しい決定事項があれば、作業前にファイルを更新しておく。

## 🛡️ Phase 1: 指示・設計段階 (Prevention)

- [ ] **「実装（Coding）」の前に「設計（Design）」を出させたか？**
    * いきなりコードを書かせようとしていないか？
    * AI:「コードを書きます！」→ 人間:「待て。まずは設計案を出せ」
- [ ] **タスクの粒度は適切か？**
    * 「会員機能を全部作って」はNG。「会員登録のAPI設計をして」まで分解する。
- [ ] **既存のDB設計・アーキテクチャとの整合性は取れているか？**
    * AIは部分最適になりがち。全体整合性は人間がチェックする。
- [ ] **「やらないこと（Out of Scope）」を伝えたか？**
    * AIは頼まれていない機能も親切心で追加しがち。「今回は認証機能以外触るな」と釘を刺す。

## 🔍 Phase 2: 実装・レビュー段階 (Quality Control)

- [ ] **提示されたコードは `CLAUDE.md` の規約を守っているか？**
    * 守っていない場合、修正指示ではなく「`CLAUDE.md` を読んで修正せよ」と指示する。
- [ ] **AIの「もっともらしい嘘（ハルシネーション）」を疑ったか？**
    * ライブラリのバージョン、非推奨メソッド、存在しないAPIが含まれていないか。
- [ ] **トラブル時、AIの提案（知識）を人間の勘（嗅覚）でフィルタリングしたか？**
    * 「ルーターの買い替え」のような的外れな提案を鵜呑みにしていないか。
    * 解決策が複雑すぎる場合、「再起動」や「基本設定」を試させたか。

## 📝 Phase 3: セッション終了時 (Context Saving)

- [ ] **`add-report` コマンドで成果を記録したか？**
    * 未来の自分のために、ログを残す。
- [ ] **新しく判明した「知見」や「ルール」を `CLAUDE.md` に追記したか？**
    * 「このエラーが出たらこうする」「このライブラリは使わない」など。
- [ ] **「技術的負債」のリファクタリング予約をしたか？**
    * 今回、急ぎで汚いコードを書かせた場合、タスクリストに「〇月〇日リファクタリング」と積んだか。
