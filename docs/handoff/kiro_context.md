## 📋 作業フロー

### 1. 新機能開発時

#### Step 1: 仕様書作成
```
1. Phase計画書で次の機能を確認
2. `/docs/specifications/features/_TEMPLATE.md` をコピー
3. 機能仕様書を作成
   - 目的・ユーザーストーリー
   - 機能要件・非機能要件
   - 画面仕様・データ仕様
   - 受け入れ基準
   - Claude Codeへの実装メモ
4. Phase計画書に仕様書作成完了を記録
```

#### Step 2: Claude Codeへ引き継ぎ
```
1. 作成した仕様書のパスを伝える
2. 実装時の注意点を伝える
3. 参考にすべき既存実装を伝える
```

#### Step 3: 実装後の検証
```
1. 受け入れ基準に沿って動作確認
2. エラーハンドリング確認
3. レスポンシブ対応確認
4. セキュリティ確認
5. パフォーマンス確認
```

#### Step 4: 仕様書更新
```
1. 実装内容を仕様書に反映
2. 実装履歴を記録
3. Phase計画書に完了を記録
4. 実装ログに記録
```

### 2. バグ修正時

```
1. 仕様書を確認（仕様通りか？）
2. 問題点を特定
3. Claude Codeに修正依頼
4. 修正後、再検証
5. 必要に応じて仕様書更新
```

### 3. 既存機能の仕様書作成

```
1. 実装コードを確認
2. 動作を確認
3. 仕様書に記述
4. Phase計画書に記録
```

## 💡 Tips

### 仕様書作成のコツ
1. **具体的に書く**: 「適切に」「良い感じに」等の曖昧な表現を避ける
2. **受け入れ基準を明確に**: 「完了」の定義を明確にする
3. **実装メモを活用**: Claude Codeへの具体的な指示を記載
4. **既存実装を参照**: 類似機能の実装を参考にする

### 検証のコツ
1. **受け入れ基準に沿って確認**: 漏れなく確認
2. **エッジケースを意識**: 境界値・異常値を確認
3. **実際のユーザー視点**: 使いやすさを確認
4. **パフォーマンスを意識**: 遅延・重さを確認

### ドキュメント管理のコツ
1. **こまめに更新**: 実装と仕様書の乖離を防ぐ
2. **履歴を残す**: 誰が・いつ・何をしたかを記録
3. **リンクを活用**: 関連ドキュメントへのリンクを明記
