## 1. 前提条件

- AWSアカウントを保有していること
- AWS Management Console へのアクセス権限
- S3バケット作成権限 / IAMユーザー作成権限
- アプリケーションサーバーへのアクセス権限（環境変数設定のため）

## 2. AWS S3 セットアップ

### 2.1 S3バケット作成

1. **AWS Management Console にログイン**
   - https://console.aws.amazon.com/

2. **S3 サービスに移動**
   - 上部の検索バーで「S3」を検索してクリック

3. **新しいバケットを作成**
   - 「バケットを作成」ボタンをクリック
   - 以下の設定を入力:

   | 設定項目 | 値 |
   |---------|-----|
   | バケット名 | `portfolio-backup-miyakawa-codes` |
   | AWS リージョン | `アジアパシフィック（東京）ap-northeast-1` |
   | オブジェクト所有権 | ACL 無効（推奨） |

   - 「バケットを作成」をクリック

> **バケット名について**: S3バケット名はグローバルに一意である必要があります。  
> 上記名前が使用済みの場合は適宜変更し、環境変数 `S3_BACKUP_BUCKET` に合わせて設定してください。

### 2.2 サーバーサイド暗号化（SSE-S3）設定

バックアップデータは必ず暗号化して保存します。

1. 作成したバケット（`portfolio-backup-miyakawa-codes`）をクリック
2. 「プロパティ」タブをクリック
3. 「デフォルトの暗号化」セクションで「編集」をクリック
4. 以下の設定を行う:

   | 設定項目 | 値 |
   |---------|-----|
   | サーバー側の暗号化 | 有効にする |
   | 暗号化タイプ | `Amazon S3 マネージドキー（SSE-S3）` |
   | バケットキー | 有効にする（コスト削減） |

5. 「変更を保存」をクリック

> アプリケーション側でも `put_object` 時に `server_side_encryption: "AES256"` を指定しており、二重の暗号化保護が適用されます。

### 2.3 パブリックアクセスブロック設定

バックアップデータが外部に公開されないよう、**全てのパブリックアクセスをブロック**します。

1. 「アクセス許可」タブをクリック
2. 「パブリックアクセスをブロック（バケット設定）」セクションで「編集」をクリック
3. 以下の **4つ全て** にチェックを入れる:

   - ✅ 新しいアクセスコントロールリスト（ACL）を介して付与されたバケットとオブジェクトへのパブリックアクセスをブロックする
   - ✅ 任意のアクセスコントロールリスト（ACL）を介して付与されたバケットとオブジェクトへのパブリックアクセスをブロックする
   - ✅ 新しいパブリックバケットポリシーまたはアクセスポイントポリシーを介して付与されたバケットとオブジェクトへのパブリックアクセスをブロックする
   - ✅ 任意のパブリックバケットポリシーまたはアクセスポイントポリシーを介したバケットとオブジェクトへのパブリックアクセスとクロスアカウントアクセスをブロックする

4. 「変更を保存」をクリック
5. 確認ダイアログに「確認する」と入力して「確認」

### 2.4 バージョニング設定

誤削除・誤上書きからの復旧を可能にするため、バージョニングを有効にします。

1. 「プロパティ」タブをクリック
2. 「バージョニング」セクションで「編集」をクリック
3. 「バケットのバージョニング」で「有効にする」を選択
4. 「変更を保存」をクリック

### 2.5 ライフサイクルルール設定（オプション）

> **注意**: Phase 7.3 では `S3RetentionManager` がアプリケーション側で世代管理を行います。  
> このステップは **任意** ですが、S3ネイティブの世代管理を追加することでより堅牢になります。

古いバックアップを自動削除するライフサイクルルールを設定します。

1. 「管理」タブをクリック
2. 「ライフサイクルルールを作成」をクリック
3. 以下の3つのルールを作成:

#### 日次バックアップ（7日間保持）

| 設定項目 | 値 |
|---------|-----|
| ルール名 | `daily-backup-retention` |
| ルールスコープ | プレフィックス: `daily/` |
| アクション | 現在のバージョンを期限切れにする |
| 日数 | `7` |

#### 週次バックアップ（28日間保持）

| 設定項目 | 値 |
|---------|-----|
| ルール名 | `weekly-backup-retention` |
| ルールスコープ | プレフィックス: `weekly/` |
| アクション | 現在のバージョンを期限切れにする |
| 日数 | `28` |

#### 月次バックアップ（365日間保持）

| 設定項目 | 値 |
|---------|-----|
| ルール名 | `monthly-backup-retention` |
| ルールスコープ | プレフィックス: `monthly/` |
| アクション | 現在のバージョンを期限切れにする |
| 日数 | `365` |

## 3. IAM 認証情報作成

バックアップ専用の IAM ユーザーを作成し、**最小権限の原則**に従ってアクセス権を付与します。

> アプリケーションの画像アップロード用（`AWS_ACCESS_KEY_ID`）とは**別の IAM ユーザー**を使用することで、権限を分離します。

### 3.1 IAMユーザー作成

1. AWS Management Console で「IAM」を検索してクリック
2. 左メニューから「ユーザー」をクリック
3. 「ユーザーを作成」ボタンをクリック
4. 以下の設定を入力:

   | 設定項目 | 値 |
   |---------|-----|
   | ユーザー名 | `portfolio-backup-user` |
   | AWS Management Console アクセス | チェックなし（プログラムのみ） |

5. 「次へ」をクリック

### 3.2 S3アクセス権限設定（最小権限の原則）

1. 「ポリシーを直接アタッチする」を選択
2. 「ポリシーを作成」ボタンをクリック（新しいタブが開く）
3. 「JSON」タブをクリックして、以下のポリシーを貼り付け:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BackupS3Access",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::portfolio-backup-miyakawa-codes",
        "arn:aws:s3:::portfolio-backup-miyakawa-codes/*"
      ]
    }
  ]
}
```

| 付与する権限 | 用途 |
|------------|------|
| `s3:PutObject` | バックアップファイルのアップロード |
| `s3:GetObject` | バックアップファイルのダウンロード（復元時） |
| `s3:DeleteObject` | 古いバックアップの世代管理削除 |
| `s3:ListBucket` | バックアップ一覧の取得 |

4. ポリシー名を入力して作成:

   | 設定項目 | 値 |
   |---------|-----|
   | ポリシー名 | `PortfolioBackupS3Policy` |

5. 「ポリシーを作成」をクリック
6. ユーザー作成タブに戻り、ポリシー一覧を更新して `PortfolioBackupS3Policy` を選択
7. 「次へ」→「ユーザーを作成」をクリック

### 3.3 アクセスキー発行

1. ユーザー一覧から `portfolio-backup-user` をクリック
2. 「セキュリティ認証情報」タブをクリック
3. 「アクセスキーを作成」をクリック
4. ユースケース: `サードパーティサービス` を選択
5. 確認チェックボックスにチェックを入れて「次へ」
6. 説明タグ（オプション）: `portfolio-rb-backup` など
7. 「アクセスキーを作成」をクリック

> ⚠️ **重要**: この画面でのみシークレットアクセスキーが表示されます。  
> 「.csv ファイルをダウンロード」して安全な場所に保管してください。  
> 画面を閉じると、シークレットアクセスキーは**二度と表示されません**。

### 3.4 環境変数設定

#### `.env` ファイルに追加

```bash
# AWS S3 Backup Configuration（バックアップ専用クレデンシャル）
AWS_BACKUP_ACCESS_KEY_ID=your_access_key_id_here
AWS_BACKUP_SECRET_ACCESS_KEY=your_secret_access_key_here
AWS_BACKUP_REGION=ap-northeast-1
S3_BACKUP_BUCKET=portfolio-backup-miyakawa-codes
```

> **変数名について**: 画像アップロード用の `AWS_ACCESS_KEY_ID` と区別するため、  
> バックアップ用は `AWS_BACKUP_` プレフィックスを使用します。

#### 本番サーバーへの設定

```bash
# Docker Compose 環境の場合（.env ファイルを更新後）
docker compose up -d --force-recreate web sidekiq

# 設定が反映されているか確認
docker compose exec web env | grep AWS_BACKUP
```

#### セキュリティ注意事項

- `.env` ファイルは `.gitignore` に含まれていることを確認
- アクセスキーは **90日ごと** のローテーションを推奨
- 本番環境では AWS Secrets Manager の使用を検討

## 4. コスト見積もり

### 想定データ量

| カテゴリ | 1回のバックアップサイズ（圧縮後） |
|---------|--------------------------------|
| データベース | 100 MB |
| Active Storage | 500 MB |
| 設定ファイル | 1 MB |
| **合計** | **601 MB** |

### 世代管理後のストレージ使用量

| 種別 | 世代数 | 合計サイズ |
|-----|-------|----------|
| 日次 | 7世代 × 601 MB | 4.2 GB |
| 週次 | 4世代 × 601 MB | 2.4 GB |
| 月次 | 12世代 × 601 MB | 7.2 GB |
| **合計** | | **13.8 GB** |

### S3ストレージコスト（ap-northeast-1）

| 項目 | 計算式 | 月額 |
|-----|-------|------|
| ストレージ（最初の50TB） | 13.8 GB × $0.025/GB | **$0.35** |

### データ転送コスト

| 項目 | 計算式 | 月額 |
|-----|-------|------|
| アップロード（S3へ） | 無料 | $0.00 |
| ダウンロード（月1回の復元テスト） | 0.601 GB × $0.114/GB | **$0.07** |

### リクエストコスト

| 項目 | リクエスト数/月 | 月額 |
|-----|--------------|------|
| PUTリクエスト（バックアップ） | 105回 | $0.001 |
| GETリクエスト（一覧取得・ダウンロード） | 33回 | $0.00001 |

### 月額合計

| 項目 | 月額コスト |
|-----|----------|
| ストレージ | $0.35 |
| データ転送 | $0.07 |
| リクエスト | $0.001 |
| **合計** | **$0.42/月** |

**日本円換算**（1ドル = 150円）: **約63円/月**

### コスト最適化のヒント

#### 1. S3 Glacier への移行

月次バックアップは参照頻度が低いため、`S3 Glacier Instant Retrieval` への移行でコスト削減可能です。

```
S3 標準: $0.025/GB/月
S3 Glacier Instant Retrieval: $0.005/GB/月（80%削減）

月次 7.2GB の場合:
  現在: 7.2 × $0.025 = $0.18/月
  移行後: 7.2 × $0.005 = $0.036/月
  年間削減: 約$1.73
```

ライフサイクルルールで自動移行を設定:
- 作成から 30日後 → S3 Glacier Instant Retrieval

#### 2. 世代管理の最適化

運用の状況に応じて世代数を調整することでコスト削減できます。

| 設定 | 削減率 | 変更箇所 |
|-----|--------|---------|
| 日次: 7日 → 5日 | 約10% | `S3RetentionManager::RETENTION_DAYS["daily"] = 5` |
| 週次: 28日 → 21日 | 約5% | `S3RetentionManager::RETENTION_DAYS["weekly"] = 21` |

#### 3. データ圧縮率の向上

現在の圧縮設定（gzip）は標準的な圧縮率です。  
データベースが大きくなった場合は `pg_dump` の圧縮レベルを調整することを検討してください。

#### 4. リージョンの検討

東京リージョン（ap-northeast-1）は低レイテンシーのため推奨ですが、  
大阪ローカルリージョン（ap-northeast-3）は若干安価な場合があります。  
ただし、レイテンシーとコストのトレードオフを考慮してください。

## 5. セットアップ確認

全ての設定が完了したら、以下の確認を行ってください。

### 環境変数の確認

```bash
docker compose exec web rails runner "
  puts 'AWS_BACKUP_REGION: ' + ENV.fetch('AWS_BACKUP_REGION', '未設定')
  puts 'S3_BACKUP_BUCKET: ' + ENV.fetch('S3_BACKUP_BUCKET', '未設定')
  puts 'ACCESS_KEY: ' + (ENV['AWS_BACKUP_ACCESS_KEY_ID'] ? '設定済み' : '未設定')
  puts 'SECRET_KEY: ' + (ENV['AWS_BACKUP_SECRET_ACCESS_KEY'] ? '設定済み' : '未設定')
"
```

### S3 接続確認

```ruby
# Rails コンソール内
begin
  s3 = S3Service.new
  backups = s3.list_backups
  puts "S3接続成功。バックアップ件数: #{backups.length}"
rescue => e
  puts "S3接続エラー: #{e.message}"
end
```

### テストバックアップの実行

```ruby
# Rails コンソール内（本番環境では注意）
BackupService.new(backup_type: "daily").execute
puts "最新バックアップ: #{BackupLog.last.inspect}"
```

### 確認チェックリスト

- [ ] S3 バケットが作成されている
- [ ] サーバーサイド暗号化（SSE-S3）が有効
- [ ] パブリックアクセスが全てブロックされている
- [ ] バージョニングが有効
- [ ] IAM ユーザー（`portfolio-backup-user`）が作成されている
- [ ] IAM ポリシー（`PortfolioBackupS3Policy`）がアタッチされている
- [ ] アクセスキーが発行されている
- [ ] 環境変数（`AWS_BACKUP_*`）が設定されている
- [ ] テストバックアップが成功している
- [ ] アクセスキーの .csv が安全な場所に保管されている
