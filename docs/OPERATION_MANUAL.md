# 仕様駆動開発 運用マニュアル

## 📋 概要

このマニュアルは、**Kiro** と **Claude Code** を併用した仕様駆動開発の運用方法を説明します。

**対象読者**: プロジェクトオーナー（人間）  
**作成日**: 2025-12-26  
**バージョン**: 1.0

---

## 🎯 基本方針

### 役割分担

| 担当 | 役割 | 主な作業 |
|------|------|---------|
| **Kiro** | 仕様管理・検証 | 仕様書作成、動作確認、ドキュメント更新 |
| **Claude Code** | 実装・設計 | コード実装、リファクタリング、バグ修正 |
| **あなた** | プロジェクト管理 | 要件定義、優先順位決定、最終承認 |

### 開発フロー

```
あなた: 機能要件を決定
  ↓
Kiro: 仕様書作成
  ↓
Claude Code: 実装
  ↓
Kiro: 検証・仕様書更新
  ↓
あなた: 最終確認・承認
```

## 🚀 新機能開発の手順

### Step 1: 要件を決める（あなた）

**やること**:
- 実装したい機能を決める
- 優先順位を決める
- Phase計画書で現在のフェーズを確認

**例**:
```
「ブログ記事の下書き自動保存機能を実装したい」
```

---

### Step 2: Kiroに仕様書作成を依頼

**Kiroへの指示例**:
```
Kiro、KIRO.mdを確認してください。

ブログ記事の下書き自動保存機能の仕様書を作成してください。
以下の要件を満たすようにお願いします：
- 30秒ごとに自動保存
- 保存中はローディング表示
- 保存成功時はメッセージ表示
- エラー時は再試行
```

**Kiroがやること**:
1. KIRO.mdを読み込んで役割確認
2. `/docs/specifications/features/_TEMPLATE.md` を使用
3. 機能仕様書を作成
   - 目的・ユーザーストーリー
   - 機能要件・非機能要件
   - 画面仕様・データ仕様
   - 受け入れ基準
   - Claude Codeへの実装メモ
4. Phase計画書に記録

**成果物**:
- `/docs/specifications/features/auto-save-draft.md`

---

### Step 3: 仕様書を確認（あなた）

**確認ポイント**:
- [ ] 要件が正しく反映されているか
- [ ] 受け入れ基準が明確か
- [ ] 実装可能な内容か

**修正が必要な場合**:
```
Kiro、仕様書を修正してください。
自動保存の間隔を30秒から60秒に変更してください。
```

---

### Step 4: Claude Codeに実装を依頼

**Claude Codeへの指示例**:
```
Claude Code、CLAUDE.mdを確認してください。

/docs/specifications/features/auto-save-draft.md の仕様書に基づいて、
ブログ記事の下書き自動保存機能を実装してください。

実装前に確認：
- /docs/handoff/claude_context.md
- /docs/handoff/conventions.md
```

**Claude Codeがやること**:
1. CLAUDE.mdを読み込んで役割確認
2. 仕様書を読み込む
3. コーディング規約に従って実装
4. 実装完了を報告

**成果物**:
- 実装コード
- 変更ファイル一覧
- 動作確認方法

---

### Step 5: Kiroに検証を依頼

**Kiroへの指示例**:
```
Kiro、Claude Codeが実装した下書き自動保存機能を検証してください。

変更ファイル：
- [Claude Codeの報告をコピー&ペースト]

動作確認方法：
- [Claude Codeの報告をコピー&ペースト]
```

**Kiroがやること**:
1. 受け入れ基準に沿って動作確認
2. エラーハンドリング確認
3. レスポンシブ対応確認
4. セキュリティ確認
5. 仕様書を実装に合わせて更新
6. Phase計画書・実装ログに記録

**成果物**:
- 検証レポート
- 更新された仕様書
- 問題点・改善点のリスト

---

### Step 6: 最終確認（あなた）

**確認ポイント**:
- [ ] 実装が要件を満たしているか
- [ ] 動作に問題がないか
- [ ] ユーザビリティは良いか

**問題がある場合**:
```
「Kiro、以下の問題を修正するようClaude Codeに依頼してください：
- 自動保存のメッセージが邪魔
- ローディング表示が小さすぎる」
```

**承認する場合**:
```
「承認します。次の機能に進んでください。」
```

## 🔧 バグ修正の手順

### Step 1: バグを報告（あなた）

**Kiroへの指示例**:
```
Kiro、KIRO.mdを確認してください。

ブログ記事の画像アップロードでエラーが発生します。
画像サイズが10MBを超えるとアップロードできません。
調査して修正してください。
```

---

### Step 2: Kiroが調査

**Kiroがやること**:
1. KIRO.mdを読み込んで役割確認
2. 仕様書を確認（仕様通りか？）
3. 問題点を特定
4. 修正方針を提案

**報告例**:
```
調査結果：
- 仕様書では5MB制限と記載
- 実装では10MB制限
- エラーメッセージが不明瞭

修正方針：
1. 制限を5MBに統一
2. エラーメッセージを改善
3. ファイルサイズを事前チェック

Claude Codeに修正を依頼してよろしいですか？
```

---

### Step 3: 修正を承認（あなた）

```
承認します。修正を進めてください。
```

---

### Step 4: Claude Codeが修正

**Kiroの指示**:
```
Claude Code、CLAUDE.mdを確認してください。

以下のバグを修正してください：
[修正内容の詳細]

実装前に確認：
- /docs/handoff/claude_context.md
- /docs/handoff/conventions.md
```

---

### Step 5: Kiroが再検証

**Kiroがやること**:
1. 修正内容を確認
2. バグが解消されたか確認
3. 副作用がないか確認
4. 仕様書を更新（必要な場合）

## 🎯 効率的な運用のコツ

### 1. 明確な指示を出す

**❌ 悪い例**:
```
ブログ機能を改善してください
```

**✅ 良い例**:
```
Kiro、KIRO.mdを確認してください。

ブログ記事一覧ページに検索機能を追加してください。
タイトルと本文を対象に、部分一致検索ができるようにしてください。
```

---

### 2. AI設定ファイルを活用

**セッション開始時は必ず確認させる**:
```
Kiro、KIRO.mdを確認してください。
```
```
Claude Code、CLAUDE.mdを確認してください。
```

これにより、各AIが自分の役割を理解して作業を開始できます。

---

### 3. 優先順位を明確にする

**指示例**:
```
Kiro、KIRO.mdを確認してください。

以下の機能を優先順位順に実装してください：
1. 画像アップロード機能（高）
2. 検索機能（中）
3. コメント機能（低）
```

---

### 4. 定期的に進捗確認

**週次確認の例**:
```
Kiro、KIRO.mdを確認してください。
今週の実装内容と来週の予定を教えてください。
```

---

### 5. 仕様書は常に最新に

**指示例**:
```
Kiro、実装が完了したら必ず仕様書を更新してください。
```

---

### 6. 問題があればすぐに報告

**指示例**:
```
Kiro、実装中に問題が発生したら、
すぐに報告して、解決策を提案してください。
```

## 📌 重要な原則

### 1. 仕様書ファースト
- 実装前に必ず仕様書を作成
- 仕様書がない機能は実装しない

### 2. ドキュメントは常に最新
- 実装後は必ず仕様書を更新
- Phase計画書・実装ログも更新

### 3. 役割分担を守る
- Kiro: 仕様管理・検証
- Claude Code: 実装
- あなた: 要件定義・承認

### 4. コミュニケーションを明確に
- 曖昧な指示を避ける
- 具体的な要件を伝える
- 期待する成果物を明確にする

### 5. 定期的な確認
- 週次で進捗確認
- 月次でPhase計画書レビュー
- 四半期で全体見直し
