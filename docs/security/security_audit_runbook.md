# セキュリティ監査手順書

## 目的
自動化されたセキュリティ監査（Brakeman / bundler-audit）と週次レポートの運用手順を明確化する。

## 前提
- GitHub Actions が有効化されている
- `INTERNAL_API_TOKEN` / `RAILS_WEBHOOK_URL` / `SECURITY_AUDIT_EMAIL` が設定済み
- 管理画面に管理者でアクセス可能

## 日次監査（自動）

1. GitHub Actions の `Security Audit` ワークフローが日次で実行される
2. Brakeman / bundler-audit の結果がアーティファクトに保存される
3. 脆弱性が検知された場合、内部API経由でアプリに通知される
4. 管理画面 `セキュリティスキャン` で結果を確認する

## 手動監査（必要時）

1. GitHub Actions の `Security Audit` を `workflow_dispatch` で実行
2. 失敗時はアーティファクトをダウンロードし、結果を確認
3. 監査結果を管理画面で確認し、必要に応じて脆弱性対応を開始

## 週次レポート（自動）

1. Sidekiq-cron により毎週月曜に `Security::WeeklyReportJob` が実行
2. `Security::ReporterService` がデータを収集してレポートを生成
3. 管理画面 `セキュリティレポート` で確認・PDFダウンロード

## 管理画面での確認ポイント

- セキュリティスキャン一覧
  - スキャン種別、ステータス、脆弱性サマリー
- スキャン詳細
  - 検出された脆弱性の内容、深刻度
- セキュリティレポート
  - 期間内のスキャン結果、脆弱性統計、インシデント統計

## 運用チェックリスト

- [ ] GitHub Actions が直近24時間以内に成功している
- [ ] 管理画面に最新スキャン結果が反映されている
- [ ] 高/重大の脆弱性に対して対応が開始されている
- [ ] 週次レポートが生成されている
