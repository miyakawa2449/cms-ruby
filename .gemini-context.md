# Project Context for Gemini CLI (Rails 8 CMS)

## 1. Tech Stack
- **Language:** Ruby 3.4.7
- **Framework:** Rails 8.1.1
- **Database:** PostgreSQL 17-alpine (Features: ICU Locale, Full Text Search enabled)
- **Background Jobs:** Sidekiq 8.0 (backed by Redis 7-alpine)
- **Frontend:**
  - **CSS:** Tailwind CSS
  - **JS:** Hotwire (Turbo & Stimulus)
  - **Assets:** Propshaft (No Webpacker/Shakapacker)
- **Infrastructure (AWS):**
  - **Compute:** Lightsail
  - **Email:** SES
  - **AI:** Bedrock (Models: Claude 4.5 Sonnet/Haiku)

## 2. Coding Standards
- **Rails 8 Way:**
  - Use `Propshaft` standards for asset paths.
  - Prefer `Turbo Frames` and `Streams` over custom JavaScript for partial updates.
  - Use `Stimulus` controllers for necessary DOM manipulations.
- **Database:**
  - Utilize PostgreSQL native features (Full Text Search) where applicable.
  - Ensure migrations are compatible with PostgreSQL 17 features.
- **Jobs:**
  - Inherit from `ApplicationJob` (using Sidekiq adapter).
  - Ensure idempotency for retries.

## 3. Workflow & Constraints
- **Commands:**
  - Run app: `docker compose up`
  - Console: `docker compose exec web bin/rails c`
  - Tests: `docker compose exec web bin/rails test` (or `bundle exec rspec` if using RSpec)
- **AI Integration (Bedrock):**
  - When modifying AI features, check the service class handling `Aws::BedrockRuntime::Client`.
  - Distinguish between `Sonnet` (complex tasks) and `Haiku` (speed/simple tasks) usage.
