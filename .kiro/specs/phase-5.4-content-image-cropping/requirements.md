# Phase 5.4: 本文内画像トリミング機能 - 要件定義

## プロジェクト概要

ブログ記事の本文内に挿入する画像に対して、アップロード時にトリミング機能を提供する。
固定サイズ（800x600px、4:3アスペクト比）でトリミングすることで、記事内の画像サイズを統一し、
読みやすく美しいレイアウトを実現する。

## ユーザーストーリー

### US-1: 画像のトリミング
**As a** 執筆者  
**I want to** 本文内画像をトリミングしたい  
**So that** 記事のレイアウトを統一できる

### US-2: 画像サイズの最適化
**As a** 執筆者  
**I want to** 画像サイズを最適化したい  
**So that** 読み込み速度を改善できる

### US-3: 記事保存前のアップロード
**As a** 執筆者  
**I want to** 記事保存前に画像をアップロードしたい  
**So that** 執筆中にプレビューを確認できる

### US-4: トリミング範囲のプレビュー
**As a** 執筆者  
**I want to** トリミング範囲をプレビューしたい  
**So that** 最適な構図を選べる

## 機能要件

### FR-1: 画像アップロード時のトリミング

#### FR-1.1: トリミングモーダルの自動表示
- 画像選択時に自動的にトリミングモーダルを表示する
- モーダルはオーバーレイ形式で表示する
- 背景をクリックまたはESCキーでモーダルを閉じられる

#### FR-1.2: アスペクト比の固定
- トリミングのアスペクト比は4:3で固定する
- ユーザーはアスペクト比を変更できない

#### FR-1.3: トリミング範囲の選択
- ドラッグでトリミング範囲を移動できる
- ハンドルをドラッグしてトリミング範囲をリサイズできる
- トリミング範囲は画像全体に対して表示する

#### FR-1.4: リアルタイムプレビュー
- トリミング範囲を変更すると、プレビューがリアルタイムで更新される
- プレビューは800x600pxのサイズで表示する

#### FR-1.5: 出力サイズ
- トリミング後の画像サイズは800x600pxとする
- JPEG形式、品質92%で出力する

### FR-2: 一時アップロード方式

#### FR-2.1: 記事保存前のアップロード
- 記事を保存していなくても画像をアップロードできる
- アップロードした画像は記事に紐付けて保存する

#### FR-2.2: Active Storageの使用
- Active Storageの`content_images`として保存する
- 記事削除時に関連画像も自動削除する

### FR-3: トリミングUI

#### FR-3.1: Cropper.jsの使用
- Cropper.jsライブラリを使用する
- インタラクティブなトリミング操作を提供する

#### FR-3.2: UI要素
- トリミング範囲の視覚的な表示
- プレビュー画像の表示（800x600px）
- alt属性の入力フィールド（必須）
- キャプションの入力フィールド（オプション）
- 保存ボタン
- キャンセルボタン
- ローディング表示

### FR-4: 画像の挿入

#### FR-4.1: Markdownコードの自動生成
- トリミング完了後、Markdownコードを自動生成する
- キャプションなしの場合: `![alt属性](画像URL)`
- キャプションありの場合: HTML形式（figure/figcaption）

#### FR-4.2: エディタへの自動挿入
- 生成したMarkdownコードをエディタのカーソル位置に自動挿入する

### FR-5: エラーハンドリング

#### FR-5.1: ファイル形式チェック
- 対応形式: JPEG, PNG, GIF, WebP
- 対応形式以外の場合、エラーメッセージを表示する

#### FR-5.2: ファイルサイズ制限
- 最大ファイルサイズ: 10MB
- 超過した場合、エラーメッセージを表示する

#### FR-5.3: アップロード失敗時の処理
- アップロード失敗時、エラーメッセージを表示する
- リトライ可能にする

## 非機能要件

### NFR-1: パフォーマンス
- トリミングモーダル表示: < 1秒
- 画像アップロード: < 5秒（5MB画像の場合）
- プレビュー更新: < 0.5秒

### NFR-2: ユーザビリティ
- 直感的なトリミング操作
- リアルタイムプレビュー
- キーボードショートカット対応（ESC: キャンセル）
- レスポンシブ対応（モバイルでも操作可能）

### NFR-3: セキュリティ
- ファイル形式の厳密なチェック
- ファイルサイズ制限の実装
- XSS対策（alt属性、キャプションのエスケープ）
- CSRF対策

### NFR-4: アクセシビリティ
- キーボード操作対応
- 適切なARIAラベル

## 制約条件

### 技術的制約
- Rails 8.1.1
- Active Storage
- Stimulus.js
- Cropper.js 1.6.0
- Tailwind CSS

### ビジネス制約
- アスペクト比は4:3固定（変更不可）
- 出力サイズは800x600px固定（変更不可）
- 1つの画像につき1サイズのみ生成
