# Phase 6: セキュリティ強化 - 要件定義

**Phase**: 6  
**作成日**: 2026-01-22  
**ステータス**: 要件定義完了  
**優先度**: 高  
**担当**: Codex（テスト・検証）

---

## 📋 概要

Phase 6 では、本番環境で稼働中のポートフォリオCMSのセキュリティを強化します。既存の基本的なセキュリティ機能（Devise認証、Rack::Attack）を拡張し、より堅牢なセキュリティ体制を構築します。

---

## 🎯 目的

1. **管理画面のセキュリティ強化**: 不正アクセスを防止
2. **セキュリティヘッダーの最適化**: XSS、CSRF、クリックジャッキング対策
3. **監視・ログ機能の強化**: 不正アクセスの検知と追跡
4. **セキュリティテストの充実**: 脆弱性の早期発見

---

## 👥 ユーザーストーリー

### US-6.1: セキュリティヘッダー強化

**As a** システム管理者  
**I want** 適切なセキュリティヘッダーが設定されている  
**So that** XSS、CSRF、クリックジャッキング攻撃から保護される

#### 受入基準

1.1 Content Security Policy (CSP) が適切に設定されている  
1.2 X-Frame-Options が設定されている（クリックジャッキング対策）  
1.3 X-Content-Type-Options が設定されている（MIME スニッフィング対策）  
1.4 Strict-Transport-Security (HSTS) が設定されている（本番環境のみ）  
1.5 Referrer-Policy が設定されている  
1.6 Permissions-Policy が設定されている  
1.7 開発環境と本番環境で適切に設定が分かれている

---

### US-6.2: 管理画面アクセス制御強化

**As a** システム管理者  
**I want** 管理画面へのアクセスが厳密に制御されている  
**So that** 不正アクセスを防止できる

#### 受入基準

2.1 ログイン試行回数制限が機能している（5回失敗で1時間ロック）  
2.2 ロックアウト時に適切なエラーメッセージが表示される  
2.3 ロックアウト解除時刻が表示される  
2.4 セッションタイムアウトが機能している（30分）  
2.5 管理画面パスが環境変数で設定可能  
2.6 不正なパスへのアクセスは404を返す（管理画面の存在を隠蔽）

---

### US-6.3: セキュリティ監視・ログ機能

**As a** システム管理者  
**I want** セキュリティイベントがログに記録される  
**So that** 不正アクセスを検知・追跡できる

#### 受入基準

3.1 ログイン成功/失敗がログに記録される  
3.2 ログアウトがログに記録される  
3.3 アカウントロック/アンロックがログに記録される  
3.4 管理画面への不正アクセス試行がログに記録される  
3.5 Rack::Attack によるブロックがログに記録される  
3.6 ログには IP アドレス、タイムスタンプ、ユーザーエージェントが含まれる  
3.7 ログは構造化されており、検索・分析が容易

---

### US-6.4: API セキュリティ強化

**As a** API 利用者  
**I want** API が適切にレート制限されている  
**So that** DoS 攻撃から保護される

#### 受入基準

4.1 API エンドポイントにレート制限が適用されている  
4.2 レート制限超過時に 429 エラーが返される  
4.3 Retry-After ヘッダーが含まれる  
4.4 内部 API と公開 API で異なるレート制限が適用される  
4.5 認証済みユーザーと未認証ユーザーで異なるレート制限が適用される

---

### US-6.5: 入力検証・サニタイゼーション強化

**As a** システム管理者  
**I want** すべてのユーザー入力が適切に検証・サニタイズされている  
**So that** SQLインジェクション、XSS攻撃から保護される

#### 受入基準

5.1 すべてのフォーム入力に適切なバリデーションが設定されている  
5.2 Markdown コンテンツが適切にサニタイズされている  
5.3 ファイルアップロードの MIME タイプが検証されている  
5.4 ファイルサイズ制限が機能している  
5.5 SQL インジェクション対策が機能している（パラメータ化クエリ）  
5.6 XSS 対策が機能している（自動エスケープ）

---

### US-6.6: セキュリティテストの充実

**As a** 開発者  
**I want** セキュリティに関する包括的なテストが存在する  
**So that** 脆弱性を早期に発見できる

#### 受入基準

6.1 セキュリティヘッダーのテストが存在する  
6.2 認証・認可のテストが存在する  
6.3 レート制限のテストが存在する  
6.4 入力検証のテストが存在する  
6.5 CSRF 対策のテストが存在する  
6.6 セッション管理のテストが存在する  
6.7 すべてのテストが成功する

## 🎯 非機能要件

### NFR-6.1: パフォーマンス

- セキュリティチェックによるレスポンスタイムへの影響は 50ms 以内
- ログ記録による処理時間への影響は 10ms 以内
- Rack::Attack のメモリ使用量は 100MB 以内

### NFR-6.2: 可用性

- セキュリティ機能の障害時もアプリケーションは正常動作
- ログ記録の失敗はアプリケーションの動作に影響しない
- レート制限の誤検知を最小化（正常なユーザーをブロックしない）

### NFR-6.3: 保守性

- セキュリティ設定は環境変数で管理
- ログは構造化されており、検索・分析が容易
- セキュリティポリシーは一元管理

### NFR-6.4: コンプライアンス

- OWASP Top 10 の主要な脆弱性に対応
- Rails セキュリティガイドに準拠
- 個人情報保護法に準拠（ログの適切な管理）

## 📊 現状分析

### 既存のセキュリティ機能

#### ✅ 実装済み

1. **Devise 認証**
   - ログイン/ログアウト機能
   - パスワードリセット機能
   - Lockable 機能（5回失敗で1時間ロック）
   - セッションタイムアウト（30分）

2. **Rack::Attack**
   - ログイン試行制限（5回/20秒）
   - パスワードリセット制限（5回/1時間）
   - API レート制限（100回/1分）
   - お問い合わせフォーム制限（5回/1時間）
   - 一般リクエスト制限（300回/5分）
   - SQL インジェクション検知

3. **Rails 標準機能**
   - CSRF トークン検証
   - SQL インジェクション対策（パラメータ化クエリ）
   - XSS 対策（自動エスケープ）

#### ⚠️ 改善が必要

1. **セキュリティヘッダー**
   - CSP が開発環境のみ設定（本番環境で未設定）
   - HSTS が未設定
   - Permissions-Policy が未設定

2. **監視・ログ**
   - セキュリティイベントのログが不十分
   - 構造化ログが未実装
   - ログ分析ツールが未整備

3. **テスト**
   - セキュリティテストが不足
   - レート制限のテストが未実装
   - セキュリティヘッダーのテストが未実装

## 🔧 技術要件

### 使用技術

- **セキュリティヘッダー**: Rails 標準機能（`config/initializers/content_security_policy.rb`）
- **レート制限**: Rack::Attack（既存）
- **ログ**: Rails.logger + 構造化ログ（JSON形式）
- **テスト**: RSpec + Capybara

### 環境変数

```bash
# 管理画面パス（デフォルト: admin）
ADMIN_PATH=admin-secure-panel-miyakawa2449

# セッションタイムアウト（分）
SESSION_TIMEOUT=30

# ログレベル
LOG_LEVEL=info

# セキュリティヘッダー設定（本番環境のみ）
ENABLE_HSTS=true
HSTS_MAX_AGE=31536000
```
