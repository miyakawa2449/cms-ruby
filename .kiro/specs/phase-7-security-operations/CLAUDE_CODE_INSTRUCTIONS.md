# Phase 7: セキュリティ・運用強化 - Claude Code実装指示書

## 📋 概要

Phase 7では、2段階認証、管理画面URL管理、自動バックアップシステム、セキュリティ監査自動化、監視機能強化を実装します。

**重要**: このフェーズはセキュリティに関わるデリケートな作業です。Codexとペアリングして進めます。

---

## 🎯 あなた（Claude Code）の役割

あなたは**実装担当**として、以下の責任を持ちます：

1. **実装**: タスクリストに従ってコードを実装
2. **基本テスト**: 実装した機能の基本的なRSpecテストを実装・実行
3. **自己チェック**: 実装が要件を満たしているか自己確認
4. **引き継ぎ**: Codexに検証を依頼（詳細な検証はCodexが担当）

## ⚠️ 重要な注意事項

### 1. 環境変数の取り扱い

**絶対にやってはいけないこと**:
```ruby
# ❌ ダメな例
email = 'tsuyoshi@miyakawa.codes'
slack_url = 'https://hooks.slack.com/services/...'
aws_key = 'AKIAIOSFODNN7EXAMPLE'
```

**正しい方法**:
```ruby
# ✅ 良い例
email = ENV['ADMIN_EMAIL']
slack_url = ENV['SLACK_WEBHOOK_URL']
aws_key = ENV['AWS_ACCESS_KEY_ID']
```

### 2. 設計書の実装例を使用

設計書には詳細な実装例があります。**これをそのまま使用してください**。

独自の実装や改善は避けてください。設計書に従うことで、以下のメリットがあります：

- ✅ 仕様との整合性が保たれる
- ✅ Codexの検証がスムーズになる
- ✅ バグのリスクが減る

### 3. 完璧を目指さない

あなたの役割は「基本的な実装」です。以下は**やらなくて良い**です：

- ❌ すべてのエッジケースのテスト → Codexが実装
- ❌ パフォーマンス最適化 → Codexが検証
- ❌ セキュリティの詳細チェック → Codexが実装

**やるべきこと**:
- ✅ 設計書に従った実装
- ✅ 正常系のテスト
- ✅ 基本的な動作確認

### 4. 不明点は質問する

以下の場合は、実装前に必ず質問してください：

- 設計書の実装例が理解できない
- 要件が不明確
- 既存コードとの統合方法が分からない
- セキュリティ上の懸念がある

**質問の形式**:

