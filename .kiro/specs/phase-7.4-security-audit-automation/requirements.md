## 🎯 概要

### Phase 7.4の目的
セキュリティ脆弱性を自動検知し、継続的なセキュリティ監査を実現する。

### 主要機能
1. **静的解析自動化**: Brakeman、bundler-audit CI/CD統合
2. **依存関係監査**: Dependabot設定最適化
3. **ログ監視・アラート**: 不正アクセス検知、エラー率監視
4. **セキュリティレポート**: 週次レポート自動生成

### 実装期間
- **開始**: 2026-02-16
- **終了**: 2026-02-20
- **期間**: 5日間

## 🌟 背景・目的

### 背景

#### 現状の課題
1. **手動セキュリティ監査**: Brakeman、bundler-auditを手動実行
2. **脆弱性発見の遅れ**: 定期的なチェックがない
3. **対応の遅延**: 脆弱性発見から修正までのタイムラグ
4. **監査証跡の不足**: セキュリティ監査履歴が不明確

#### Phase 6での実装内容
- セキュリティヘッダー強化
- SecurityLogger実装
- Rack::Attack最適化
- 入力検証強化
- 91件のセキュリティテスト

### 目的

#### 1. 脆弱性の早期発見
- 日次自動スキャンによる早期検知
- CI/CD統合による継続的監査
- 新規脆弱性の即時検知

#### 2. 対応の迅速化
- 脆弱性発見時の即時通知
- 自動PR作成による修正支援
- 対応状況のトラッキング

#### 3. 監査証跡の確保
- セキュリティスキャン履歴の記録
- 週次レポートによる可視化
- コンプライアンス対応

高

## 🔧 機能要件

### FR-7.4.1: 静的解析自動化

#### FR-7.4.1.1: Brakeman CI/CD統合
- **実行頻度**: 日次（毎日午前9時JST）
- **実行トリガー**: 
  - スケジュール実行（cron）
  - プルリクエスト作成時
  - mainブランチへのpush時
- **スキャン対象**: 
  - app/
  - config/
  - lib/
- **出力形式**: JSON、HTML
- **通知条件**: 
  - 新規脆弱性発見時
  - 重大度が「High」以上の場合

#### FR-7.4.1.2: bundler-audit CI/CD統合
- **実行頻度**: 日次（毎日午前9時JST）
- **実行トリガー**: 
  - スケジュール実行（cron）
  - Gemfile.lock更新時
  - プルリクエスト作成時
- **スキャン対象**: Gemfile.lock
- **データベース更新**: 実行前に自動更新
- **通知条件**: 
  - 脆弱性発見時
  - 重大度が「Medium」以上の場合

#### FR-7.4.1.3: GitHub Actions ワークフロー
- **ワークフロー名**: `security-audit.yml`
- **ジョブ構成**:
  1. Brakemanスキャン
  2. bundler-auditスキャン
  3. 結果の集約
  4. 通知送信
- **成果物**: 
  - スキャン結果（JSON、HTML）
  - GitHub Actionsアーティファクトとして保存
- **失敗時の動作**: 
  - ワークフロー失敗
  - 通知送信
  - ログ記録

### FR-7.4.2: 依存関係監査

#### FR-7.4.2.1: Dependabot設定
- **チェック頻度**: 日次
- **対象ファイル**: 
  - Gemfile
  - package.json
- **自動PR作成**: 
  - 脆弱性発見時
  - バージョンアップデート時
- **PR内容**: 
  - 脆弱性の詳細
  - CVE番号
  - 推奨される対応
  - 変更履歴（CHANGELOG）

#### FR-7.4.2.2: 自動マージ戦略
- **自動マージ条件**: 
  - パッチバージョンアップデート（x.x.X）
  - テストが全て成功
  - 重大度が「Low」以下
- **手動レビュー必須**: 
  - メジャーバージョンアップデート（X.x.x）
  - マイナーバージョンアップデート（x.X.x）
  - 重大度が「Medium」以上

#### FR-7.4.2.3: ラベル付与
- **重大度ラベル**: 
  - `security: critical`
  - `security: high`
  - `security: medium`
  - `security: low`
- **タイプラベル**: 
  - `dependencies`
  - `security`

### FR-7.4.3: ログ監視・アラート

#### FR-7.4.3.1: 不正アクセス検知
- **検知対象**: 
  - ログイン失敗（5回以上/10分）
  - 管理画面への不正アクセス試行
  - Rack::Attackによるブロック
  - 2FA失敗（3回以上/10分）
- **アラート条件**: 
  - 同一IPからの連続失敗
  - 異常なアクセスパターン
- **通知先**: 
  - メール（SECURITY_AUDIT_EMAIL）
  - Slack（#security-alerts）

#### FR-7.4.3.2: エラー率監視
- **監視対象**: 
  - 500エラー
  - 422エラー（CSRF）
  - 403エラー（認可失敗）
- **閾値**: 
  - エラー率 > 5%（10分間）
  - 500エラー > 10件/分
- **通知先**: 
  - メール（ADMIN_EMAIL）
  - Slack（#alerts）

#### FR-7.4.3.3: 異常トラフィック検知
- **検知対象**: 
  - リクエスト数の急増（通常の3倍以上）
  - 特定エンドポイントへの集中アクセス
  - 異常なUser-Agent
- **アラート条件**: 
  - 1分間のリクエスト数 > 1000
  - 同一IPからのリクエスト > 100/分
- **通知先**: 
  - メール（ADMIN_EMAIL）
  - Slack（#alerts）

### FR-7.4.4: セキュリティレポート

#### FR-7.4.4.1: 週次レポート生成
- **実行頻度**: 毎週月曜日午前10時JST
- **レポート内容**: 
  1. **サマリー**: 
     - 新規脆弱性数
     - 修正済み脆弱性数
     - 未対応脆弱性数
  2. **Brakemanスキャン結果**: 
     - 重大度別の脆弱性数
     - 新規脆弱性の詳細
  3. **bundler-auditスキャン結果**: 
     - 脆弱性のあるgem一覧
     - CVE番号
     - 推奨バージョン
  4. **対応状況**: 
     - 対応中の脆弱性
     - 対応完了の脆弱性
     - 対応予定の脆弱性
  5. **セキュリティインシデント**: 
     - 不正アクセス試行数
     - ブロックされたIP数
     - エラー発生状況

#### FR-7.4.4.2: レポート配信
- **配信方法**: 
  - メール（SECURITY_AUDIT_EMAIL）
  - 管理画面での閲覧
- **フォーマット**: 
  - HTML（メール）
  - PDF（ダウンロード可能）
- **保存期間**: 52週間（1年）

#### FR-7.4.4.3: 管理画面統合
- **レポート一覧画面**: 
  - 週次レポート一覧
  - 日付、サマリー表示
  - ダウンロードボタン
- **レポート詳細画面**: 
  - 全セクションの表示
  - グラフ・チャート表示（Chart.js）
  - PDF出力機能
